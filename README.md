# Life OS

通过日常对话整理生活记录、学习数据与知识库，分别保存分析报告和知识复习历史。

## 公开保存规则

公开学习数据、知识点和脱敏报告。原话与回答原文仅在用户逐次指定后上传；其他内容保留本地。公开来源使用记录 ID，不嵌入未经指定的原文、回答片段或第三方信息。事实、主观感受与分析推断分别标记；缺失信息不补造。

## 两条流程

生活记录：自然描述 → 信息提取 → 必要追问 → 简短全方位分析 → 保存回执 → 日月季年复盘。

知识学习：提取知识点 → 待诊断池 → 每次少量新题 → 用户作答 → 理解评价 → 复习队列 → 后续复习。

当天新知识先保存，不要求当天全部作答。未回答不算答错。题量不固定，根据当次可用精力调整；每批具体数量待试用。新题与到期题分开列出，复习不阻塞生活报告。

## 目录约定

- records/YYYY/MM/YYYY-MM-DD/：获准公开的学习数据和逐次授权的原文。
- reports/daily/YYYY/MM/：每日脱敏报告。
- reports/monthly/YYYY/：月度报告。
- reports/quarterly/YYYY/：季度报告。
- reports/yearly/：年度报告。
- knowledge/items/：知识点及来源 ID。
- knowledge/attempts/YYYY/MM/DD/：作答表现数据；回答原文须逐次授权。
- knowledge/review-plans/：待诊断池、复习队列与安排。
- revisions/：修订记录。

## 复习设计状态

优先级分层：核心内容精细诊断与调度，常规内容阶梯复习，低优先度便利优先。具体间隔、核心算法和低优先度是否定期抽查尚待确定。理解程度与复习阶段分开记录，单次答对不等于长期掌握。算法与规则版本随记录保存。

## 报告与修订

报告注明统计范围、生成时间、数据版本与缺失情况，结论引用记录。补记归入事件日期并保留提交日期；更正保留修订历史，相关报告标记待更新。关联不直接解释为因果。

目前仅初始化记录约定，没有真实生活或作答数据，没有后台定时生成、提醒或推送。周期报告可在对话中按请求生成；完整保存流程需用真实记录验证。
