# 动态复习：目标需求、记忆证据、优先级与轮次

版本review-v3，2026-10-12。依据用户上传的新设计来源实施其推荐顺序：先完成目标需求、分层排序和自适应轮次；记忆间隔继续采用ladder-v2冷启动，积累足够证据后再评估个体化间隔。当前没有启用概率遗忘曲线或自动学习权重。

## 1. 目标需求

每个知识点仍只有一个KP-ID、一份记忆与复习状态；各目标关系分别记录：

| 字段 | 含义 |
|---|---|
| relation / relevance | 大纲直接要求、重要前置、一般相关、无关或不确定 |
| mastery_requirement | recognition基础识别、understanding理解、application熟练运用、integration综合迁移，或null |
| requirement_basis | 该掌握要求的来源和解释；已知要求必须有依据 |
| importance | 该目标内重要性；未知为null |
| exact_date（目标档案） | 仅使用明确日期，月级目标不臆造具体考试日 |

required表示大纲直接要求，不代表每次考试必考。一般相关仍须有匹配依据；未核验关系不作为有效关联。

需求缺口按各目标的要求和对应维度的最近证据计算，输出met/partial/unmet/unknown。基础识别看recall，理解看explain，熟练运用看apply，综合迁移还须有独立迁移证据。不能凭一个词形答对认定综合应用已达标，也不凭大纲章节名称推定所有知识的掌握层级。本次未知要求保留null，后续逐项匹配时补充。

正式复习需同时满足：内容核验、已测试、存在有效范围测试证据、已有合法的记忆日期，以及有效活跃目标关联。资料待核验进入verification_pending；有部分证据但未完成有效初次调度的进入assessment_pending，用户主动诊断时补测。未测知识仍在intake。

## 2. 记忆状态与调度

review.grade继续计算1/3/7/14/30/60/90天阶梯，旧证据、阶段与日期不因这次升级改变。memory是可重建的证据摘要：

- state：consolidation待巩固、short_term短期保持、stable_retention稳定保持、long_term长期验证、unverified证据不足。
- observed_stability_days：最近一次正式失败之后、不同日期的足间隔独立稳定成功，其实际间隔的中位数。无证据则null。
- risk：high/due/watch/low/unknown，来自到期情况、逾期程度和最近表现的规则标签，不是个人遗忘概率。
- next_review：引用现有schedule.due，不维护第二套日期。

稳定保持需至少两次实际间隔不短于7天的足间隔独立稳定成功；长期验证需至少两次不短于30天的同类成功，正式错误或提示后重新积累。一天内多次成功只计一次，早复习、费力、提示、查阅、独立性未知、即时练习和目标强化不算长期间隔通过。旧证据没有间隔信息时不补造。

初期正常复习仍由due决定资格，风险标签用于排序，不推算额外的“高遗忘概率”日期。目标临近不会把未到期且稳定的知识塞入正常复习。将来的个体化间隔模块尚未启用；adaptive_intervals_enabled=false。

目标强化使用显式mode=reinforce，可以选择未到期的正式知识，按目标需求练习，更新能力证据但强制不改schedule。同一天强化/讲解/即时练习之后的测试不能冒充延迟记忆测试；当日已经测试的范围不重复派正式间隔任务。

## 3. 分层排序

先筛必要性，再比较风险层，随后处理收益和负担：

1. 排除归档、无活跃关联、未核验、未完成有效检测、本轮已处理及正常模式下未到期的知识。
2. 风险层0：到期且最近遗忘/概念错误/未知关键错误或提示，或缺少应用证据、阻碍后续目标学习的前置知识。
3. 风险层1：其他高风险、已逾期、费力答对或长期未独立验证的到期知识；层2：普通到期知识。
4. 同一风险层内，综合目标相关性、掌握缺口、目标内重要性、明确日期紧迫性和目标重要性，并兼顾目标与模块的分布。

存在7天内明确截止日期且已有明确掌握缺口时，允许同风险层集中于该目标；它仍不能越过更高风险层。有明确依据的局部失误不等同严重遗忘，仍按原阶梯缩短间隔。风险更高的基础缺口可排在临近考试但稳定的知识之前。没有百分制总分或未经校准的复杂权重。

每个动作返回reasons、风险层、目标需求、任务意图及估计时间，便于解释。它们随本轮生成，默认不永久保存完整任务清单。关联多个目标的知识每轮只出现一次，列出共同服务的目标。

## 4. 自适应轮次

| 轮次 | 默认最多范围 | 用途 |
|---|---:|---|
| light轻量 | 3 | 小批量，未知时长暂按每范围5分钟估计 |
| standard标准 | 5 | 默认轮次；不足就少出 |
| deep深度 | 8 | 用户主动选更大批量；不强行增加无必要复习 |

轻量3、深度8是可配置工程默认，不是来源给定的科学结论。用户明确指定数量可覆盖默认上限。未提供可用时间时不假设其日程；指定minutes后只选预计可完成的任务。时长未知默认10分钟，轻量/低精力5分钟，后续可校准。

数量是知识范围数量，不是题目数量。task_intent指向独立提取、解释、应用或迁移，题干、题数和选项由助手依据现场表现临时生成；不写题库。同一范围可以用几道子题评价，合并成一次有效正式调度。

一轮回答完成后保存精简证据，重新读取最新知识，重新排序下一轮，不预先生成整天任务。没有强制每日数量或每日轮次上限。即时巩固单独进行，不重复推进阶梯。

## 命令

```sh
python scripts/learning.py --day 2026-10-12
python scripts/learning.py --day 2026-10-12 --profile light --minutes 10
python scripts/learning.py --day 2026-10-12 --profile deep --minutes 40
python scripts/learning.py --day 2026-10-12 --review-limit 7
python scripts/learning.py --day 2026-10-12 --mode reinforce --focus-goal G-UPGRADE
python scripts/learning.py --day 2026-10-12 --mode diagnose --new-limit 2
```

--assigned KP-ID可重复提供，表示当前轮已处理知识，仅存在内存/当前对话。新目标要求通过lifecycle.py match的--mastery-requirement和--requirement-basis设置；传已核实的章节，不使用占位大纲。脚本输出计划，助手临时出题；评价用lifecycle.evaluate，保存用lifecycle.save，GitHub仍由助手提交核对。
