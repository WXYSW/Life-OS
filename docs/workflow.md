## 每次记录

1. 读取当前状态、相关目标、已有当日记录和修订；相同事件关联而不重复统计。
2. 将用户原文先写入本地私密记录，分配稳定 ID，保存提交时间、事件日期、时区。未知日期进入待定区。
3. 提取事实、主观感受、估计值；助手推断独立标记并引用依据。缺失使用 null，不以零填补。不把计划当成果。
4. 只追问影响判断的信息；用户说先不保存时只讨论。“简单记录”降低追问和题量。
5. 每次简短分析一个主要进展或卡点，必要时给一个建议。建议未被采纳不视为用户承诺。
6. 同日多次记录更新同一日报，标记截至时间；“今天结束”后标记完整整理。补记仍可修订。
7. 从描述中提取值得保留的知识；核验事实性知识，区分个人经验、观点和助手补充。重复概念关联已有条目。原始来源保留溯源；可训练知识进入待诊断池，不维护独立资料收藏。
8. 对允许公开的字段制作独立公开文件，检查无未授权原话、回答片段和第三方私人信息。GitHub 更新前读取最新文件和分支头，用 SHA 防止覆盖并发修改。读取核对后才报告已同步。
9. 回执包含记录 ID、本地与远程状态、文件或提交链接、未确认项。失败保留待同步，不覆盖原始记录。

## 知识诊断与复习

学习决策以 [learning-engine.md](learning-engine.md) 为准：读取目标、能力结构、知识证据，再运行learning.py规划。目标重要性未知保留null；优先级旧标签仅保留为兼容信息。日常先处理待评价回答，再续题，并按目标份额安排诊断、补学、应用和延迟复习。

知识点与题目必须有稳定 ID。先存评价标准再展示题目；答案在用户回答后展示。记录真实作答日期、提示/查阅情况、问题版本、表现、理解证据和规则版本。回答原文、片段和评价默认保存到公开 GitHub，无需逐次授权；用户当次明确排除时遵从排除。

理解状态：未评估、需要提示、能独立解释、能应用、延迟后仍能应用。不要给伪精确百分比分；回忆、解释、应用的证据分别保留。材料不同、题型难度不同不能直接比较。含糊答案可以追问，未确定不调度。

采用ladder-v2：初学、短期巩固、长期保持三个阶段。基础间隔1、3、7、14、30天，稳定长期证据可延长到60、90天。独立正确区分费力/稳定/迁移；费力不升阶，提示或遗忘/概念缺口进入1→3→7天巩固，不直接恢复旧长间隔。有明确依据的局部失误适度缩短；未知错误按巩固处理。实际间隔不足不升阶；近期多次失败暂缓延长。30天及以上须两次足间隔独立通过才延长。跳过不变；讲解/即时练习不推进，同日同知识只改变调度一次。具体判断与参数见schedule-policy.md。

核心与常规使用相同阶梯；v2不再用全局core标签代替目标贡献。低优先度默认参考归档，再次需要时激活。知识优先级、理解状态、调度阶位彼此独立。逾期保留原到期日，不批量补算，不伪造复习事件。

## 复盘与目标

日报短；每周主要复盘；月度检查目标与策略；季度与年度总结长期成果、变化和决策。各自按周期归档，每份报告包含范围、生成时间、数据版本、覆盖/缺失、证据 ID、局限、下一步。周期未完标记“截至某日”。用原始依据检查跨周期摘要，不能只层层总结。

对话时检查已经结束且尚无报告的周期，有足够记录时生成；没有数据则说明缺失，不制造报告。无后台提醒。

当前状态保留最多三个主要目标、完成标准、证据、卡点、下一步和待确认问题。建议效果、决策理由、目标变更追加记录。更正源数据时列出依赖它的报告并标记 stale，更新后记录对应版本。

## 知识点为中心的轻量存储（2026-10-11）

长期核心是 knowledge/items/ 中的知识点、分类、掌握维度、薄弱点和精简证据。knowledge/review-plans/queue.json 只是调度索引；更新时与知识点的调度字段同次提交，不能各自改成不同日期。分层目录按实际测试范围去重，父模块结果不能传给未测试子项。

题干、选项、答案原文、完整答题流水、未回答列表和派题会话不再进入 GitHub。题目只在当前对话临时生成；先确定评价要点，再出题，回答后评价。当前对话可续接部分回答，跨聊天按知识点重新出题；未答、暂停或放弃不算错、不制造欠题。当前对话用临时 assigned_ids/canonical_ids 防重复，不写持久化题目队列。同日调度仍由 last_review 防止重复推进。

评价后只保存精简证据：稳定事件ID、日期、知识点标准范围、表现结果、独立/提示/查阅情况、评价维度、费力/稳定/迁移质量、错误类型、薄弱点及依据。依据写短评价理由，不复制题目或答案。未知情况保留 null，不能补造独立或延迟证据。每个范围分别评价；混合结果应分范围保存，整个调度单位按明确关键错误与原规则判定，不用平均正确率代替。事件ID用于幂等；纠正评分要保留精简修订并按时间重算，不能重复推进。

历史诊断已提取到各知识点 diagnostic_evidence；新评价由 scripts/learning.py 的 record_evidence 保存精简 learning_events 并生成范围证据。两者只保留可用于复习判断的信息。允许累计精简证据，避免截断后失去长期验证依据。catalogue.py 从知识点派生证据覆盖和统计，不依赖独立题库或完整attempt文件。评价后同步知识点、queue、目录节点的证据索引和统计、current；脚本为纯函数，不会自动上传。

ladder-v2 的间隔 1、3、7、14、30、60、90 天及晋降级条件保持不变。保留 review_phase、stage、due、last_review、scheduled_interval_days、consolidation_passes、long_interval_passes、recent_review_outcomes 等足够调度状态。独立正确区分费力/稳定/迁移，提示或概念/遗忘进入短期巩固；早复习不升阶，30天以上须两次足间隔独立通过，练习/讲解不推进，跳过不改日期。详见 schedule-policy.md。

复习数量由用户当次选择，未指定先给5道，无每日上限；新诊断默认2道，不足不凑题。调用 python scripts/learning.py --day YYYY-MM-DD，按目标、贡献、前置条件、薄弱点与到期情况规划，再临时出题。needs_validation先核验，paused与reference不安排。C/Shell的73条保持暂时归档；明确恢复时仅恢复知识状态，重新出题，不恢复旧题或补做积欠。

持续公开授权保留，但学习默认只公开精简证据和状态。用户说不保存/不公开时遵从该次范围。日常记录的原文保存规则不受此学习存储变更影响。删除当前版本的题目文件不会删除 Git 历史，本次不重写历史；导入学习资料属于原始知识来源，保留。
