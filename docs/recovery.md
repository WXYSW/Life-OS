# 状态恢复流程 v1

目的：项目中断、忘记进度或原路径受阻时，降低重新进入的成本。沿用 records、reports、state，不新增调度模块。

## 重新进入

1. 读取 state/current.md，再读取相关最近记录、修订和报告；报告过期时回到原始记录。
2. 用五项信息定位：项目目的、当前进度、最近完成的事、当前卡点、相关文件位置。未知明确写“待确认”，不要求重新理解全部历史资料。
3. 提出一个可在短时间内完成的最小动作，写清完成标准；用户暂不执行时保留为建议。低精力时可只确认进度，复习题量允许为零。
4. 原路径失败时记录具体阻碍及已试动作，再判断继续、缩小范围或更换路径。更换系统时保存旧资料入口和未完成事项。
5. 实际执行后，按记录流程保存结果、证据和剩余卡点，更新当前状态。没有执行证据时不标记“已恢复”。

## 暂停时的交接信息

在 state/current.md 对应项目下保留以下简短信息；只维护当前需要继续的项目，不另建完整项目管理系统。

```text
项目目的：
当前进度／最近完成（证据或文件）：
卡点／已试动作：
下一步最小动作（建议或已确认）：
完成标准：
相关文件：
待确认：
```

## 如何判断是否有帮助

下次实际恢复时记录“选择了什么动作、是否完成、仍卡在哪里”；时长只有用户提供才记录。单次迁移不能证明流程有效，不生成恢复评分或自动提醒。

设计依据：[2026-10-10 系统迁移补记](../reports/daily/2026/10/2026-10-10.md)。恢复失败原因和新系统的长期效果仍待验证。
