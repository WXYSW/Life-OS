# 学习闭环 v2

生效2026-10-11，用户授权按助手设计实施。目标→能力/任务→知识→学习动作→实际证据→下次安排。生活记录与周期报告继续沿用workflow。

## 数据与依据

- goals/initial.json：目标状态、用户重要性high/medium/low或null、具体日期、完成标准、差距、时间预算及证据。未知不填零；月级期限不能当精确考试日。重要性须来自用户，差距须有测评依据。
- knowledge/capabilities.json：真实任务示例、所需能力与知识ID；初始结构仅部分覆盖，不是完整考试大纲。
- knowledge/items/：goal_links按目标分别记贡献high/medium/low及理由、依据；capability_ids、prerequisite_ids、内容难度、时长估计。前置关系只用于已核验依赖，缺失引用和循环报错。无前置边仅表示尚未建模。
- mastery分别保存recall/explain/apply的unknown/gap/supported/demonstrated、依据及时间；延迟和迁移证据单独记录。不能从一次答对推导长期掌握，也不能从两道题推算目标总差距。
- queue负责调度状态，items负责知识内容和证据；当前对话临时记住实际派题。旧priority保留，low仍默认不新派，core不再自动优先于目标贡献。

## 可解释决策

1. 先列出待评价回答，由助手评价后重新规划；这些不占出题额度。知识未经核验、暂停、参考归档不自动选入。当前对话已有题不能重复派；临时知识ID和标准范围做批内去重。
2. 未完成题优先续接，使用原题ID；延期未到恢复日、暂停题不派。旧题占对应新题/复习额度。用户明确focus时只选择该目标的映射知识，其余题继续保留。
3. 新动作仅选择active目标下已映射的知识；用户指定focus可临时选择长期目标，不永久改变目标状态。缺少目标映射的候选先由助手核验和补映射，不猜考试贡献。
4. 活跃目标临时份额：用户重要性high/medium/low对应3/2/1，未知中性1；有精确日期且30天内到期加1，有证据的大差距加1。这是可解释的初始规则，非学习科学定律，不自动学习权重。按本批已分配的预计分钟/份额轮流选目标，避免只选最高权重目标。小批次不保证每个目标都有内容；跨批长期份额由周复盘检查。
5. 同一目标内：续题优先；贡献高优先；作为其他知识前置的基础优先；已有薄弱证据优先；然后到期日、估计成本、稳定ID。前置知识尚无独立应用证据时，新的后续动作阻塞并列出原因；当前对话未答题仍允许继续以收集证据。
6. pending→diagnose；到期且需提示/补学→relearn；到期但缺少应用证据→apply；已有应用证据→delayed_review。续题→continue_question。不会自动新派未到期复习。用户主动要提前巩固时由助手记录practice，不推进阶梯。
7. 数量由用户决定；无固定每日上限，默认新题2、复习5是批量。minutes为本批时间预算，只纳入能装入预算的动作。时长未知使用临时10分钟，低精力5分钟，输出明确标记估计。低精力时由助手缩小任务、减少步骤，不能把5分钟当已测耗时。

## 分层目录与去重（2026-10-11）

## 知识点为中心的轻量存储（2026-10-11）

长期核心是 knowledge/items/ 中的知识点、分类、掌握维度、薄弱点和精简证据。knowledge/review-plans/queue.json 只是调度索引；更新时与知识点的调度字段同次提交，不能各自改成不同日期。分层目录按实际测试范围去重，父模块结果不能传给未测试子项。

题干、选项、答案原文、完整答题流水、未回答列表和派题会话不再进入 GitHub。题目只在当前对话临时生成；先确定评价要点，再出题，回答后评价。当前对话可续接部分回答，跨聊天按知识点重新出题；未答、暂停或放弃不算错、不制造欠题。当前对话用临时 assigned_ids/canonical_ids 防重复，不写持久化题目队列。同日调度仍由 last_review 防止重复推进。

评价后只保存精简证据：稳定事件ID、日期、知识点标准范围、表现结果、独立/提示/查阅情况、评价维度、费力/稳定/迁移质量、错误类型、薄弱点及依据。依据写短评价理由，不复制题目或答案。未知情况保留 null，不能补造独立或延迟证据。每个范围分别评价；混合结果应分范围保存，整个调度单位按明确关键错误与原规则判定，不用平均正确率代替。事件ID用于幂等；纠正评分要保留精简修订并按时间重算，不能重复推进。

历史诊断已提取到各知识点 diagnostic_evidence；新评价由 scripts/learning.py 的 record_evidence 保存精简 learning_events 并生成范围证据。两者只保留可用于复习判断的信息。允许累计精简证据，避免截断后失去长期验证依据。catalogue.py 从知识点派生证据覆盖和统计，不依赖独立题库或完整attempt文件。评价后同步知识点、queue、目录节点的证据索引和统计、current；脚本为纯函数，不会自动上传。

ladder-v2 的间隔 1、3、7、14、30、60、90 天及晋降级条件保持不变。保留 review_phase、stage、due、last_review、scheduled_interval_days、consolidation_passes、long_interval_passes、recent_review_outcomes 等足够调度状态。独立正确区分费力/稳定/迁移，提示或概念/遗忘进入短期巩固；早复习不升阶，30天以上须两次足间隔独立通过，练习/讲解不推进，跳过不改日期。详见 schedule-policy.md。

复习数量由用户当次选择，未指定先给5道，无每日上限；新诊断默认2道，不足不凑题。调用 python scripts/learning.py --day YYYY-MM-DD，按目标、贡献、前置条件、薄弱点与到期情况规划，再临时出题。needs_validation先核验，paused与reference不安排。C/Shell的73条保持暂时归档；明确恢复时仅恢复知识状态，重新出题，不恢复旧题或补做积欠。

持续公开授权保留，但学习默认只公开精简证据和状态。用户说不保存/不公开时遵从该次范围。日常记录的原文保存规则不受此学习存储变更影响。删除当前版本的题目文件不会删除 Git 历史，本次不重写历史；导入学习资料属于原始知识来源，保留。
