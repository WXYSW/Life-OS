# 知识点与待回答题的细节流程

版本 questions-v1，更新2026-10-11。本文件与workflow、HANDOFF同步；真实用户记录才改变队列。

## 三种不同对象

1. 知识条目：knowledge/items/。直接发来的资料与日常提取内容走同一路径；合并重复概念，未经核验标needs_validation，核验后训练内容标pending，参考资料标reference。不因保存而认定会了。
2. 已派题：knowledge/questions/backlog.json。只记录实际向用户发出的题，不能把准备好的diagnostic_question当已派题。包含稳定题目ID、knowledge_id、kind（new/review）、题目文本、版本、issued_on、评价要点、回答片段、事件历史与状态。
3. 复习状态：knowledge/review-plans/queue.json。pending没有到期日，实际回答完成评估后才成为review；原有复习题未答时维持原阶段和due。

状态：unanswered未答，partial部分回答，awaiting_evaluation可评估但尚未处理，deferred本轮跳过，paused暂停，evaluated已评价，cancelled替换或撤销。关闭条目也保留用于追溯；长期列表不在午夜清空。

## 开始/继续复习

先读知识队列、backlog、当天session。先处理awaiting_evaluation；再选择最重要的未完成题，由learning.py在续题优先的前提下按目标份额及知识证据选择，然后补新题和到期动作。已有新题占新题额度、已有复习题占复习题额度。新题默认每批最多2道；复习按用户当次数量，未指定先5道，可继续追加或随时停止，无固定每日上限；如果两道新题都没答，不再加两道新题。积压条目保留，只展示本轮少量。

排除已有开放题对应知识（含暂停、延期、待评价），避免同一知识重复出新题或复习题。当日assigned_ids仅阻止新派题，不能阻止继续原来的题。实际展示的题目ID加入session，延续题关联原ID与issued_on，不改为今天新题。

问题拟定并核验评价要点后，先提交backlog和session，再展示题目。提交失败则给出未同步状态，不能当已可靠保存；下一轮核对重试，ID不变。不先展示答案。评价要点可包含主题而不必提前公开参考答案。

## 回答与评价

用户只回答某一道时，只更新该题；题目对应不明确则简短确认，不猜。后续回答原文、部分回答和评价默认获授权保存到公开 GitHub，无需逐次询问；当次明确排除公开或保存时遵从排除。跨聊天缺失的原文明确标缺失，只在评价确有需要时补充，不能编造历史回答。

部分回答追加answer_fragments，标partial，不因缺少另一半判整题错误，不调整整题复习日期。继续问尚缺部分；如果已足够评价，助手明确确认并标awaiting_evaluation。若原题包括多个独立知识点，应拆为子题或独立题，各自评估，不让一个未答部分阻塞已完成知识点。

完成评价时一次提交：attempts作答历史、backlog状态evaluated、知识条目理解证据、queue的新阶段/到期日、当前状态。使用实际完成可评估回答的日期计算间隔；不是派题日期或后来处理日期。迟处理并已过到期时保留真实到期日期。单日同知识不连续升阶。

每次回答/状态事件有稳定event_id，同一事件重试不重复追加。同ID不同内容属修订，不复用旧event_id覆盖。更正评价追加revisions并按有效历史重算，不修改旧事实。

## 跳过、暂停与替换

- “这次跳过”：deferred，默认次日可续接，不算答错；要本日继续可明确恢复。
- “暂停这个知识”：题与知识条目标paused，保存之前状态/due，停止自动选题，不清空理解证据。恢复后恢复原调度，逾期不算错误。
- “只归档”：知识reference，对应开放题cancelled，取消理由和历史保留。
- “换一道”：原题cancelled并记录替代ID，新题显式创建；同一天session仍保留原派题，用户明确换题才允许有理由地超出默认派题去重限制。
- 长期未回答：不自动删除、不自动降级。复盘时可以提议归档，但用户同意后执行。

## 说明同步与能力边界

每次新记录、派题、部分回答、评价、跳过/暂停等操作都更新相应状态文件和state/current.md；改变长期规则时同一次提交同步workflow、HANDOFF、本文件、config及相关脚本。README提供入口，日期写明真实修改日。保存完成后读取核对。

“实时更新”指当前对话操作完成后及时提交和核对，不代表全天后台监听。纯函数questions.issue/change/plan不保存文件；助手负责把返回状态及其他关联文件原子提交GitHub。脚本CLI只输出计划，不能报告为已实际派题或已完成评价。

## 自主复习量（2026-10-11）

复习总量由用户当次意愿决定，不设固定每日上限：指定数量就按数量安排；未指定时先给5道（只是起始批量），用户说继续可追加，说停或暂停即停。助手负责选题、难度、讲解和间隔；新诊断默认每批最多2道，可按需求调整。优先续接未完成题和到期薄弱点，不足不凑题。额外巩固与到期复习区分记录，同一天同知识不重复推进阶梯。
脚本 `--review-limit N` 指定本批复习量，`--new-limit N` 指定本批新题量，0可暂停对应类别；默认5只是起始批量。数量按当批计算，续题占对应额度。

## 学习动作与证据

候选动作不是派题。学习动作实际发生后按templates/learning-event.json记录；需要回答的动作关联原有题目生命周期。助手拟题、先确定评价标准，再原子保存backlog、session及current后展示。record_evidence返回新的知识状态，调用方同时追加attempt、更新queue/backlog/current；讲解和即时练习不升阶。详见learning-engine.md。
