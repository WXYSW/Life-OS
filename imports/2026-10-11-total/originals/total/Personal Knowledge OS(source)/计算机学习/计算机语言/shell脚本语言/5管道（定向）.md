最简单的重定向是 `< file` 和 `> file`。这两个命令可以将程序的输入输出流分别重定向到文件：

```
missing:~$ echo hello > hello.txt
missing:~$ cat hello.txt
hello
missing:~$ cat < hello.txt
hello
missing:~$ cat < hello.txt > hello2.txt
missing:~$ cat hello2.txt
hello
```
重定向只要>就可以了相当于覆盖了


`>>` 来向一个文件追加内容==`|`== 操作符允许我们将一个程序的输出和另外一个程序的输入连接起来：
```
missing:~$ ls -l / | tail -n1
drwxr-xr-x 1 root  root  4096 Jun 20  2019 var
missing:~$ curl --head --silent google.com | grep --ignore-case content-length | cut --delimiter=' ' -f2
219
```
ls -l /
列出根目录 (/) 下所有文件和目录的详细信息（权限、所有者、大小、修改时间等）。

| tail -n1
通过管道 (|) 将上述结果传递给 tail，-n1 表示只显示最后一行。

输出解析：
drwxr-xr-x：目录权限（所有者可读/写/执行，其他用户可读/执行）
1：链接数
root root：所有者和所属组
4096：目录大小（字节）
Jun 20 2019：最后修改时间
var：目录名称

结论：
显示根目录中按字母排序的最后一个条目（这里是 var 目录的详细信息）。
curl --head --silent google.com
向 google.com 发送 HTTP HEAD 请求（只获取响应头，不下载正文），--silent 隐藏进度信息。

| grep --ignore-case content-length
过滤响应头，忽略大小写匹配包含 Content-Length 的行（例如：Content-Length: 219）。

| cut --delimiter=' ' -f2
用空格作为分隔符，提取第二个字段（即 219）。

输出解析：
219 是 Google 服务器返回的 HTTP 响应头中 Content-Length 的值，表示正文长度（单位：字节）。

深层含义：
这个值通常很小（此处仅 219 字节），因为：

Google 可能返回了 HTTP 重定向（如 301/302），响应头中包含一个简短的重定向说明 HTML。

HEAD 请求本身不返回实际内容，但服务器可能仍会声明一个预期的正文长度。


 ==|==  管道符号，将上一步的输出传递给这个命令
