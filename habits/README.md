# 习惯养成表

本表只追踪用户明确批准加入的习惯。助手可以在日常、周度或阶段总结时，根据已有记录提出有依据的习惯建议；建议不等于已启用，必须由用户明确批准后才加入本表。

## 状态定义

- `proposed`：助手提出，等待用户批准；不计入正式习惯。
- `active`：用户已批准，纳入后续记录和总结。
- `paused`：用户决定暂时暂停。
- `retired`：用户决定停止追踪，历史保留。

## 每日生活记录计数器

这与习惯打卡计数分开。它的意义是记录生活积累了多少、以后可以回顾自己走过的经历。

- 每完成并保存一份“每日生活记录”，记录次数加 1。
- 同一天补充或修改同一份记录，不重复计为新的记录；累计记录天数按有记录的不同日期计算。
- 计数器不评价一天过得好不好。平淡、疲惫、迷茫或遇到挫折的日子同样值得记录。
- 隔一段时间，尤其用户情绪低落时，主动提供过往经历回顾：呈现真实发生过的事、面对过的困难与变化，不只聚焦问题和改进。
- 不确定历史总数时先核对文件，不编造数字。当前核对到的正式每日生活记录为 1 份（2026-10-14），涉及 1 个不同日期；计数详情见 [生活记录计数器](../records/life-log-counter.json)。

## 建议与批准流程

1. 助手在总结中指出观察到的模式，或推荐一个具体、可执行的习惯，并简述依据与预期用途。
2. 将建议标为待批准；未经批准不得放入正式追踪表。
3. 用户明确同意后，记录习惯内容、频率/标准、开始日期与状态 `active`。
4. 日常记录只依据实际提供的信息更新；没有报告不等于未完成，未知保持未知。
5. 在总结中评估习惯是否有帮助，避免仅凭短期相关性断言因果。用户可以随时修改、暂停或停止。

## 当前执行边界

- 这是记录与回顾机制，不是后台提醒或自动打卡系统。
- 不擅自把一般建议、计划或偶尔做过的事转成习惯。
- 习惯数据与生活记录分开管理，但可在总结时结合分析。
- 推荐优先小而可持续的行为；一次只引入少量新习惯，避免追踪负担过重。
